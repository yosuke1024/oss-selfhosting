# notes/

Optional long-form observations that do not fit a record field: cost behaviour
over time, upgrade friction, operational surprises, why a route was rejected.

**Layout:** `notes/<product-slug>/<YYYY-MM-DD>-<topic>.md`, dated because a
note is a snapshot of one moment and is not maintained as current.

**Notes are always optional.** Nothing depends on a note existing, and no part
of the contract reads one.

**Rules:**

- A note never states a check result. Results live in the verification block on
  the product record, where the schema can validate them and the validator can
  refuse an unsupported claim. A note that contradicts a record means the
  record needs fixing.
- A note is not a listing and does not make a product listed.
- Date every note and leave it dated. Notes are not edited to stay current;
  write a new one.
- Same publication rules as everywhere else: public information only, no
  credentials, no account identifiers.
